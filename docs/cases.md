# 三个独立应用案例

TraceCell 本体把三个 MiniCPM 模型串成一条流水线。但每个模型也都能单独
跑成一个完整案例——输入、处理、输出，各自独立交付。

```bash
tracecell case ocr 票据.png    # 案例一：只解析
tracecell case jev 票据.png    # 案例二：只质检
tracecell case vlm 票据.png    # 案例三：看图问答
```

加 `--format json` 可以拿到机器可读的结果。

---

## 案例一：带坐标的单据解析

**模型**：MiniCPM-OCR 1.0（1.3B）
**解决什么**：把纸质单据变成**带坐标**的结构化数据。

普通的 OCR 输出是一段文本，用完就没了：知道"金额是 145,318.00"，不知道
它长什么样、从哪来的，也没法回头核对。这个案例的输出是每个块的坐标和
内容：

```json
{
  "case": "ocr",
  "models": ["MiniCPM-OCR 1.0"],
  "summary": {"regions": 21, "chars": 846, "profile": {...}},
  "regions": [
    {"id": "r012",
     "bbox": {"x0": 0.113, "y0": 0.516, "x1": 0.329, "y1": 0.529},
     "category": "text",
     "text": "价税合计（小写）￥145,318.00"}
  ]
}
```

坐标是归一化值（0~1，左上原点），可以直接叠在原图上做高亮，也可以把单块
裁出来单独处理。

**交付形态**：一个 REST 接口（`POST /parse`），或者 CLI 一行命令。适合直接
嵌进现有的单据处理管线。

## 案例二：给 OCR 结果做质检

**模型**：MiniCPM-OCR 1.0 + MiniCPM-OCR Jev（2B）
**解决什么**：把一堆 OCR 结果分成"能自动采用"和"得人工看"两堆。

这是 Jev 最直接的用法，也是绝大多数团队接入 Jev 时的第一件事。注意这个
案例**不做任何修复**——它只负责告诉你哪里不可信：

```json
{
  "case": "jev",
  "models": ["MiniCPM-OCR 1.0", "MiniCPM-OCR Jev"],
  "summary": {
    "regions": 21,
    "scored": 20,
    "auto_accept": 15,
    "need_review": 6,
    "mean_score": 0.8802,
    "threshold": 0.9,
    "auto_accept_rate": 0.7143
  }
}
```

其中 `need_review` 里有两种东西，输出里分开标：

- **真低分**：模型跑出来了，但认为读得不对
- **没跑成**：`verdict` 不是 `scored`。图像解码失败、渲染失败、前向失败时
  服务会返回固定分数，那是"没跑成"而不是"跑出来说不对"。混为一谈会制造
  一整轮无意义的返工

**交付形态**：一个质检接口，输出每块分数 + 自动放行清单 + 待复核清单。

**这个案例单独拿出来也能参赛**：它是很多团队需要的最小可用单元。

## 案例三：看图问答与视觉定位

**模型**：MiniCPM-V 4.7（35B-A3B）
**解决什么**：处理前面两个模型都搞不定的疑难区域。

```bash
tracecell case vlm 票据.png --question "价税合计的大写金额是什么？"
```

两种用法：

1. **整页问答**：给一张图提一个具体问题
2. **区域复核**：把存疑的那块裁出来，问一个可证伪的窄问题

第 2 种是闭环成立的关键。答案短、可判定，可以直接变成新的候选，再交给
Jev 复评：

```
区域 r012 初次解析  → Jev 0.31  →  升级复核问"是 145,318.00 还是 145,818.00？"
                  → V 4.7 回答 145,318.00  →  Jev 复评 0.94  →  放行
```

宽泛的问题（"请描述这块内容"）会产生一段散文，没法自动核验，闭环就断了。

**交付形态**：一个复核接口，输入是裁剪图 + 窄问题，输出是可判定的新候选。

## 三个案例合起来是什么

```
   图像
    │
    ▼
┌─────────────────────┐
│ 案例一：OCR 1.0     │  带坐标的区域与候选
└──────────┬──────────┘
           ▼
┌─────────────────────┐
│ 案例二：Jev         │  每块的可信度
└──────────┬──────────┘
           │ 低分 / 分歧
           ▼
┌─────────────────────┐
│ 案例三：V 4.7       │  疑难区域的裁决
└──────────┬──────────┘
           ▼
      证据账本 + 复核清单
```

单独跑，每个是一个能交付的应用；串起来，是一条端到端闭环。
